# Памятка к защите. Работа 2, вариант 31

ЧТО ДЕЛАЕТ ПРОГРАММА

Программа показывает, какие пакеты нужны выбранному пакету Ubuntu.
Она сама скачивает и читает список Packages, находит зависимости,
обходит граф и рисует его. Устанавливать пакеты она не пытается.

Например, A зависит от B, а B зависит от C.
B — прямая зависимость A. C — транзитивная, то есть через другой пакет.

КАК ВСЁ ПРОХОДИТ

1. Получаем параметры командной строки.
2. Читаем индекс Ubuntu или учебный JSON.
3. Сохраняем связи в словаре: имя пакета -> множество зависимостей.
4. Обходим граф рекурсивным DFS, проверяем глубину и фильтр.
5. Формируем текст DOT и передаём его Graphviz для создания PNG.
6. Если есть --ascii, показываем также текстовое дерево.

DFS означает обход в глубину: идём по одной ветке, затем возвращаемся
к оставшимся. Рекурсия — функция вызывает саму себя для дочерних узлов.

ПОЧЕМУ ПРОГРАММА НЕ ЗАВИСАЕТ НА ЦИКЛЕ

Запоминается лучшая, то есть минимальная, глубина посещения узла.
Если снова пришли к нему с такой же или большей глубиной, обход
не повторяется. Если нашли более короткий путь, узел обрабатывается
повторно: теперь можно увидеть больше его зависимостей в пределах лимита.

Глубина корня — 0. При глубине 1 видны только прямые зависимости.
Максимум 100 выбран как безопасная граница рекурсивного обхода.

Текстовое дерево размещает узлы по кратчайшим расстояниям от корня.
Для этого вспомогательно рассчитываются уровни очередью.
Сам граф зависимостей строится именно рекурсивным DFS.

ВОПРОСЫ И ОТВЕТЫ

«Запусти программу».
Открываю PowerShell в папке проекта и выполняю:

    .\run.bat --package A --repo examples/tree.json --test-repo --ascii

«Покажи настоящий пакет».

    .\run.bat --package bash --max-depth 2 --ascii --output output/bash.png

«Где запускается программа?»
src/__main__.py, функция main. Она получает настройки и вызывает run.

«Где параметры и обработка неправильного ввода?»
src/config.py: parse_config и validate. Используется argparse.

«Где скачивание?»
src/download.py: download_index. Используется стандартный urllib.
gzip и lzma распаковывают индекс. TLS-проверка не отключается.

«Где извлечение зависимостей?»
src/packages.py: stanzas читает поля, dependency_names извлекает имена,
parse_packages собирает граф. Берутся Depends и Pre-Depends.
Менеджеры пакетов и сторонние библиотеки для этого не используются.

«Где рекурсия?»
src/graph.py: dependency_graph и вложенная функция visit.
visit вызывает себя для каждой подходящей зависимости.

«Где тестовый режим?»
src/repository.py: load_repository выбирает источник.
load_test_repo читает JSON с именами из больших латинских букв.

«Покажи обратные зависимости».
Запускаю версию stages/stage4 с пакетом D и файлом examples/tree.json.
Получаю D -> B -> A. Это означает: B использует D, A использует B.
src/reverse.py переворачивает рёбра, затем применяется тот же DFS.

«Где рисунок?»
src/visualize.py: to_dot формирует описание, render_png запускает dot.
Graphviz используется только для рисования уже готового графа.

«Что означают пометки?»
cycle — связь замыкает цикл; shown above — узел уже показан;
link — связь к узлу другого уровня, развёрнутому в другом месте дерева.
Ромб на PNG — виртуальный пакет. Пунктир provider ведёт к поставщику.
Красный пунктирный узел — имя зависимости отсутствует в выбранном индексе.

«Почему результат может отличаться от apt?»
Здесь показываются обе альтернативы aa | bb, а не выбирается одна.
У виртуального пакета показаны доступные поставщики.
Версии не решаются, Recommends и Suggests не входят в граф.
Используется один индекс, поэтому важны версия Ubuntu и компонент main.
Это граф объявленных зависимостей, а не готовый план установки.

«Где тесты?»
В tests. Запуск: .\test.bat. В конце должно быть OK.

«Где этапы и коммиты?»
Пять этапов сохранены пятью Conventional/Scoped-коммитами и метками
stage1 ... stage5. Отдельные копии находятся в соседней папке stages.
Команда просмотра: git log --oneline --decorate.

ЧЕМ ЭТО ОТЛИЧАЕТСЯ ОТ ПЕРВОЙ РАБОТЫ

Первая работа была эмулятором оболочки с командами ls, cd, touch.
Здесь запускается одна команда с параметрами, программа выдаёт результат
и заканчивает работу. Приглашения username@hostname:~$ здесь не будет.
